# Smarty 免费账号快速切换方案（实施计划）

目标：在仅使用免费账号的前提下，尽快绕过失效账号，避免阻塞流程；对不可恢复错误直接跳过，降低 429/防护触发概率。

## 策略要点
- **硬错误立即切换**：将 402/401/429 等视为不可恢复，命中即切换下一个账号，不再累计 5 次。
- **失败阈值降低/冷却**：连续失败阈值降到 1–2；账号失败后进入冷却（如 5–10 分钟）再试，避免永久禁用。
- **并发与节流**：Smarty 并发从 3 降到 1–2；每次请求间随机 sleep（如 100–300ms）平滑流量。
- **跳过失败**：所有账号都不可用时，跳过当前地址并标记“未校验”，不中断整体。
- **日志可见性**：warn/error 中打印账号 idx/ID 尾巴 + 错误码；统计 402/429/其他的数量。
- **小批验证**：先跑 20–50 条地址验证切换与失败率，再全量。

## 具体实施步骤
1) 错误分类  
   - 在 Smarty 错误映射处区分 HTTP 状态：硬错误(>=400 且常见 401/402/429) 立即返回特殊标记；软错误（超时/网络）仍走重试。
2) 账号状态管理  
   - 将连续失败阈值改为 1–2；记录失败时间戳，冷却期内标记不可用，冷却后自动恢复尝试。  
   - `next_client_idx` 过滤掉冷却中的账号，轮询下一个。
3) 并发与延迟  
   - 下调 Smarty 查询并发（buffer_unordered 设为 1–2）。  
   - 每次请求后加随机 sleep(100–300ms)。
4) 失败处理  
   - 当所有账号不可用时，返回“未校验”标记，继续处理下一个地址。  
   - 统计失败原因，输出到日志/汇总。
5) 日志增强  
   - warn/error 打印账号 idx/ID 尾部 + HTTP 状态码/错误类型。  
   - 总结 402/429/其他的计数，便于评估免费账号可用性。
6) 小批测试  
   - 先在 20–50 条地址上试运行，确认账号切换和跳过逻辑正常，再放大到全量。

## 风险与取舍
- 免费账号缺少 us-core-cloud 订阅会持续 402，切换也无效；该策略只能减少等待，不解决订阅限制。
- 并发降低会拉长总耗时；通过缓存/增量抓取可抵消部分时间成本。
