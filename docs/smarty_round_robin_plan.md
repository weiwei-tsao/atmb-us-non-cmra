# Smarty 轮询优化方案（免费账号场景）

目标：对多账号均匀轮询，每次请求切换，避免单账号短时间内触发速率/配额/防护；对硬错误快速跳过。

## 策略
- **请求级轮询**：每个 lookup 都换下一个账号（成功也轮换），而不是同一账号连续多次。可用全局游标取模。
- **硬错误即跳**：402/401/429 等立即切换到下一账号，不累积多次失败；仍记录失败计数。
- **冷却与恢复**：硬错误的账号进入短冷却（如 5–10 分钟），冷却后再尝试，避免永久禁用。
- **并发与节流**：Smarty 并发 1–2；每次请求后随机 sleep（100–300ms）平滑流量。
- **耗尽策略**：当所有账号都不可用时，标记当前地址为“未校验”并继续，不阻塞全局。
- **日志可见性**：在日志中打印账号 idx/ID 尾部及状态码；统计 402/429/其他数量，方便评估。

## 实施要点
1) 轮询调度：全局 cursor 每次递增取 mod，总是返回下一个可用账号（不要求连续成功才能留在当前账号）。
2) 错误分类：硬错误直接标记失败+冷却；软错误保留有限重试。
3) 并发/延迟：降低 `buffer_unordered` 并发到 1–2，加入随机延迟。
4) 结果处理：全账号耗尽时给地址打“未校验”标识，继续下一条。
5) 验证：先用 20–50 条样本跑一遍，检查日志中账号轮换是否均匀、硬错误是否快速切换，再全量跑 2000+。
